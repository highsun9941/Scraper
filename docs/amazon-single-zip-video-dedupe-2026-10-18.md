## 수정 동작

- 크기에 따라 나누지 않고 미디어와 보고서를 ZIP 하나에 넣는다. `maxZipMB`로 분할하던 동작은 제거했다. 기본 원본 파일 상한은 `Infinity`이며, 명시한 `maxFileMB`는 계속 적용한다.
- 파일 크기·디렉터리 오프셋·항목 수가 기존 ZIP 필드 한계를 넘으면 ZIP64 메타데이터를 쓴다. 브라우저 Blob·메모리·디스크 한계까지 없앤 것은 아니다.
- 실제 Amazon 영상 ID 또는 트랜스코딩 자산이 같은 원본은 묶는다. HLS 마스터를 우선하며 실패하면 같은 영상의 다른 실제 원본을 시도한다. 별개 주소라도 파일 전체 바이트가 같은 영상은 한 번만 저장한다. CRC는 사전 필터이고 최종 판단에는 전체 바이트 비교를 사용한다.
- 제목이 같다는 이유로 영상을 제외하지 않는다. 서로 다른 ID와 다른 인코딩으로 재게시된 영상 전체를 시각적 유사도로 자동 판별하는 기능은 아니다.
- 실제 저장 파일을 y 오름차순, 같은 y에서는 x 오름차순으로 정렬해 이미지·GIF·영상에 공통 연속 번호를 붙인다. 실패·중복 URL은 별도 후보 `order`를 보존하며 파일 번호를 소비하지 않는다.
- 고화질 대표 URL이 뒤늦게 발견돼도 같은 영상에서 관찰한 가장 앞쪽 위치를 사용한다. 현재 DOM에서 사라진 항목의 과거 좌표는 `positionBasis:last-observed`로 구분한다. 위치를 관찰한 적 없는 항목은 뒤에 두고 좌표를 비워 둔다.
- `duplicates.csv`와 JSON에 대표 파일·제외 근거를 남긴다. 원본 요청 실패 후 다른 화질로 저장한 경우 실패한 시도도 `attempts`에 남긴다. 재생목록만 저장했을 때 임시 영상 별칭을 완전 수집으로 오인하지 않는다.

## 최종 브라우저 검증의 남은 항목

다운로드 완료 이벤트 감시를 시도한 뒤 원래 탭의 검사 연결이 붙지 않았다. 새 검증 탭에서는 일반 DOM 조회가 가능했으나 CDP 명령은 문서 응답 처리 대기 상태로 거부됐다. 브라우저 연결 복구 후에도 원래 탭의 최종 실행 상태를 읽지 못해 중복 다운로드를 피하고자 추가 실행을 중단했다.

따라서 수정본의 실제 페이지 URL 전수 대조, 최종 단일 ZIP 바이트 전수 검사, Windows 다운로드 폴더의 최종 파일 재열기는 미완료다. 이전 버전의 검증 결과나 이번 기준 영상 재생 결과를 수정본의 다운로드 완료 증거로 사용하지 않는다. Chrome 검사 연결을 복구한 뒤 위 수정본을 다시 실행하고 이 세 항목을 확인해야 한다.
